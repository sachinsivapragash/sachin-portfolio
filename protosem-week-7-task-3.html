IFTTT + Adafruit IO IoT Automation

← Week 7Task 1Task 2Task 3Task 4Task 5

01Overview

The objective is to automate the system so it reacts to an event without anyone pressing a button. An IFTTT applet watches for a trigger and writes an action to an Adafruit IO feed, which the ESP32 already listens to.

02Concepts

IoT automation

A system that senses a condition or event and acts on it by itself, with no manual input.

IFTTT

A service that connects apps and devices through applets built on the rule If This, Then That.

Trigger → Action

The trigger is the event being watched; the action is what happens in response. Here the action sends a value to an Adafruit IO feed.

Role of Adafruit IO

The feed is the bridge: IFTTT writes to it and the ESP32 receives the value over MQTT.

03System Design

"Okay Google, activate Bulb On"→IFTTT applet→bulb-control feed→ESP32 subscriber→Relay→230V AC Bulb

Saying the phrase fires a Google Assistant trigger in IFTTT, and the applet's action writes a value straight to the bulb-control Adafruit IO feed. Adafruit IO, acting as the MQTT broker, holds that value; the ESP32 is subscribed to the same feed, so the instant a new value lands it runs processBulbCommand() and switches the relay. The ESP32 has no way to tell whether the value came from a person tapping a dashboard switch or a voice command firing an applet — both are just MQTT publishes to a feed it's already listening to.

04Hardware & Software

Hardware

  • ESP32 Dev Module (WROOM-32)
  • 5V single-channel relay module
  • 230V AC bulb & holder (mains-powered)
  • Jumper wires + mains cable to the relay
  • Phone with Google Assistant, for speaking the voice command

Software & platforms

  • IFTTT account with the Google Assistant and Adafruit services connected
  • Adafruit IO account — feed bulb-control, dashboard Bulb Control
  • Arduino IDE 2.3.10
  • Adafruit IO Arduino + Adafruit MQTT libraries
  • WiFi.h for the network connection

05Wiring / Setup

This is mains-voltage wiring, not the 3.3V/5V logic side, so I kept every AC joint taped down and double-checked by hand before powering it on — the ESP32 itself never touches mains, it only switches the relay's coil. The physical circuit doesn't change when IFTTT is added on top: the relay and bulb are still driven purely by whatever value lands on RELAY_PIN, regardless of what wrote that value to the feed.

06Implementation

// task3_ifttt_automation.ino
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

// =================================================
// Wi-Fi
// =================================================

#define WIFI_SSID "protosem"
#define WIFI_PASS "Proto#123"

// =================================================
// Adafruit IO
// =================================================

#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883
#define AIO_USERNAME    "sachinn__s"
#define AIO_KEY         "YOUR_NEW_ADAFRUIT_IO_KEY"

// =================================================
// RELAY
// =================================================

#define RELAY_PIN 23

// Relay logic
#define RELAY_ON  HIGH
#define RELAY_OFF LOW

// =================================================
// MQTT
// =================================================

WiFiClient client;

Adafruit_MQTT_Client mqtt(
  &client,
  AIO_SERVER,
  AIO_SERVERPORT,
  AIO_USERNAME,
  AIO_KEY
);

// =================================================
// BULB FEED
// =================================================

Adafruit_MQTT_Subscribe bulbControl =
  Adafruit_MQTT_Subscribe(
    &mqtt,
    AIO_USERNAME "/feeds/bulb-control"
  );

// =================================================
// CONNECT TO WIFI
// =================================================

void connectWiFi() {

  Serial.print("Connecting to WiFi");

  WiFi.begin(WIFI_SSID, WIFI_PASS);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println();
  Serial.println("WiFi Connected!");
  Serial.print("IP Address: ");
  Serial.println(WiFi.localIP());
}

// =================================================
// CONNECT TO ADAFRUIT IO
// =================================================

void connectMQTT() {

  while (!mqtt.connected()) {

    Serial.print("Connecting to Adafruit IO...");

    int8_t ret = mqtt.connect();

    if (ret == 0) {
      Serial.println("Connected to Adafruit IO!");
    }
    else {
      Serial.print("Failed, error = ");
      Serial.println(mqtt.connectErrorString(ret));

      mqtt.disconnect();
      delay(5000);
    }
  }
}

// =================================================
// PROCESS BULB COMMAND
// =================================================

void processBulbCommand(String command) {

  command.trim();
  command.toLowerCase();

  Serial.print("Received command: ");
  Serial.println(command);

  // -------------------------
  // BULB ON
  // -------------------------

  if (command == "1" ||
      command == "on" ||
      command == "bulb on" ||
      command == "bulbon") {

    digitalWrite(RELAY_PIN, RELAY_ON);

    Serial.println(">>> BULB ON");
  }

  // -------------------------
  // BULB OFF
  // -------------------------

  else if (command == "0" ||
           command == "off" ||
           command == "bulb off" ||
           command == "bulb of" ||
           command == "bulboff" ||
           command == "of") {

    digitalWrite(RELAY_PIN, RELAY_OFF);

    Serial.println(">>> BULB OFF");
  }

  // -------------------------
  // UNKNOWN
  // -------------------------

  else {

    Serial.print("Unknown command: ");
    Serial.println(command);
  }
}

// =================================================
// SETUP
// =================================================

void setup() {

  Serial.begin(115200);

  delay(1000);

  Serial.println();
  Serial.println("================================");
  Serial.println("ESP32 BULB CONTROL");
  Serial.println("================================");

  // Relay setup
  pinMode(RELAY_PIN, OUTPUT);

  // Start with bulb OFF
  digitalWrite(RELAY_PIN, RELAY_OFF);

  // WiFi
  connectWiFi();

  // Subscribe to feed
  mqtt.subscribe(&bulbControl);

  // MQTT
  connectMQTT();

  Serial.println("System ready!");
}

// =================================================
// LOOP
// =================================================

void loop() {

  // Reconnect WiFi if necessary
  if (WiFi.status() != WL_CONNECTED) {
    connectWiFi();
  }

  // Reconnect MQTT if necessary
  if (!mqtt.connected()) {
    connectMQTT();
  }

  // Keep MQTT connection alive
  mqtt.processPackets(1000);

  // Check for new feed value
  Adafruit_MQTT_Subscribe *subscription;

  while ((subscription = mqtt.readSubscription(100)) != NULL) {

    if (subscription == &bulbControl) {

      String command = String((char *)bulbControl.lastread);

      processBulbCommand(command);
    }
  }
}

Key sections, in my own words:

  • Wi-Fi + Adafruit IO connection — connectWiFi() joins the protosem network and prints the assigned IP once connected. The Adafruit_MQTT_Client object is set up with my Adafruit IO username and key so connectMQTT() can authenticate to io.adafruit.com on port 1883, retrying every 5 seconds if the handshake fails.
  • Subscribing to the feed IFTTT writes to — bulbControl is an Adafruit_MQTT_Subscribe pointed at sachinn__s/feeds/bulb-control, and mqtt.subscribe(&bulbControl) in setup() tells the broker to push me every new value on that feed. The ESP32 has no idea whether that value came from a dashboard tap or a voice command — both arrive as the exact same kind of MQTT publish, which is what makes stacking IFTTT on top possible without touching this part.
  • processBulbCommand() — the incoming string is trimmed and lowercased, then matched against several ON variants (1, on, bulb on, bulbon) and OFF variants (0, off, bulb off, bulboff, of) before driving RELAY_PIN HIGH or LOW with digitalWrite(). The IFTTT action is configured to send exactly 1 or 0, both of which this function already handles, so no new cases were needed for the voice trigger to work.
  • Serial logging — Serial.print("Received command: ") followed by Serial.println(">>> BULB ON/OFF") logs every command as it arrives, which is how I confirmed each voice-triggered value actually reached the board while testing.
  • Reconnect logic in loop() — every pass checks WiFi.status() and mqtt.connected() and reconnects either one if it dropped, then calls mqtt.processPackets(1000) and reads the subscription queue, so a brief Wi-Fi hiccup doesn't leave the relay stuck out of sync with the feed.

07Configuration

  1. In IFTTT, create a new applet and pick Google Assistant → Activate scene as the trigger, then connect the Google Assistant service to my account
  2. Choose Adafruit → Send data to Adafruit IO as the action, and authorize IFTTT to read/write my Adafruit IO feed data
  3. Set the action's feed to bulb-control and the data to save to 1, then review and finish the applet
  4. Repeat the same flow for a second applet with the scene name Bulb off, sending 0 instead

I also linked IFTTT from the Google Home app itself, under Settings → Works with Google → search "IFTTT" — this is the mobile-side equivalent of the "Connect" step above and confirms the two accounts are talking to each other from the phone I actually speak the command into.

09Challenges & Fixes

  • One applet could only ever turn the bulb ON — my first instinct was that a single "Bulb" scene could toggle the light, but an IFTTT Activate-scene trigger only fires an action, it can't read the bulb's current state to flip it. I had to create a second, separate applet with its own scene name (Bulb off) and its own action sending 0, so ON and OFF are really two independent automations that happen to write to the same feed.
  • IFTTT couldn't write to my feed until I authorized it — the first attempt at the action step just sat there, and I realized I hadn't granted the Adafruit authorization request yet. Approving the "Read and write to your feed data" permission on the Adafruit account page let the action actually save.
  • Making sure the value matched what the sketch expects — since processBulbCommand() already accepts 1/0 exactly, I just had to type those values into the "Data to save" field rather than leaving IFTTT's default text in place.

10Reflection

What stood out most is how little the ESP32 side had to change for a completely different kind of trigger. Task 2 proved that publish/subscribe decouples the dashboard from the device, and this task pushed that further: IFTTT is just another publisher on the same feed, alongside the dashboard toggle, and the ESP32 never needs to know which one sent the value. That's the real payoff of building on Adafruit IO rather than hardcoding a single control path.

The automation does have a seam, though — needing two separate applets for ON and OFF instead of one smart toggle shows that IFTTT's Activate-scene trigger only knows how to fire a fixed action, not read or branch on current state. Anything more conditional (say, "turn off only if it's already on") would need a service on IFTTT's Pro tier or logic added back on the ESP32 itself.
