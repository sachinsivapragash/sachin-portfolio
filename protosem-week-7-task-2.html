Adafruit IO Dashboard & MQTT

← Week 7Task 1Task 2Task 3Task 4Task 5

01Overview

The objective is to control the ESP32 from anywhere, not only from the local network. Adafruit IO hosts the dashboard and acts as the MQTT broker, so a switch on the dashboard reaches the ESP32 through the cloud.

02Concepts

Adafruit IO

A cloud IoT platform that stores data in feeds and shows it on dashboards with switches, gauges and charts.

MQTT

A lightweight publish/subscribe protocol built for small devices. Devices exchange short messages through a broker instead of talking to each other directly.

Publisher, Subscriber, Broker

The dashboard switch publishes a message, the ESP32 subscribes to receive it, and Adafruit IO is the broker that passes it between them.

Topic / Feed

A topic is the named channel messages travel on. In Adafruit IO each feed maps to a topic, for example username/feeds/led.

03System Design

Adafruit IO dashboard toggle→bulb-control feed (MQTT broker)→ESP32 subscriber→Relay module→230V AC Bulb

Tapping the switch on the Bulb Control dashboard publishes a value to the bulb-control feed. Adafruit IO, acting as the MQTT broker, holds that value. The ESP32 is subscribed to the same feed, so as soon as a new value arrives it runs processBulbCommand() and switches the relay — no port forwarding or fixed IP needed on my end, since the ESP32 only ever reaches out to Adafruit IO's servers.

04Hardware & Software

Hardware

  • ESP32 Dev Module (WROOM-32)
  • 5V single-channel relay module
  • 230V AC Bulb & holder (mains-powered)
  • Jumper wires + mains cable to the relay

Software & platforms

  • Adafruit IO account (feed + dashboard)
  • Arduino IDE 2.3.10
  • Adafruit IO Arduino + Adafruit MQTT libraries
  • WiFi.h for the network connection

06Implementation

// task2_adafruit_mqtt.ino
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

// =================================================
// Wi-Fi
// =================================================

#define WIFI_SSID "protosem"
#define WIFI_PASS "Proto#123"

// =================================================
// Adafruit IO
// =================================================

#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883
#define AIO_USERNAME    "sachinn__s"
#define AIO_KEY         "YOUR_NEW_ADAFRUIT_IO_KEY"

// =================================================
// RELAY
// =================================================

#define RELAY_PIN 23

// Relay logic
#define RELAY_ON  HIGH
#define RELAY_OFF LOW

// =================================================
// MQTT
// =================================================

WiFiClient client;

Adafruit_MQTT_Client mqtt(
  &client,
  AIO_SERVER,
  AIO_SERVERPORT,
  AIO_USERNAME,
  AIO_KEY
);

// =================================================
// BULB FEED
// =================================================

Adafruit_MQTT_Subscribe bulbControl =
  Adafruit_MQTT_Subscribe(
    &mqtt,
    AIO_USERNAME "/feeds/bulb-control"
  );

// =================================================
// CONNECT TO WIFI
// =================================================

void connectWiFi() {

  Serial.print("Connecting to WiFi");

  WiFi.begin(WIFI_SSID, WIFI_PASS);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println();
  Serial.println("WiFi Connected!");
  Serial.print("IP Address: ");
  Serial.println(WiFi.localIP());
}

// =================================================
// CONNECT TO ADAFRUIT IO
// =================================================

void connectMQTT() {

  while (!mqtt.connected()) {

    Serial.print("Connecting to Adafruit IO...");

    int8_t ret = mqtt.connect();

    if (ret == 0) {
      Serial.println("Connected to Adafruit IO!");
    }
    else {
      Serial.print("Failed, error = ");
      Serial.println(mqtt.connectErrorString(ret));

      mqtt.disconnect();
      delay(5000);
    }
  }
}

// =================================================
// PROCESS BULB COMMAND
// =================================================

void processBulbCommand(String command) {

  command.trim();
  command.toLowerCase();

  Serial.print("Received command: ");
  Serial.println(command);

  // -------------------------
  // BULB ON
  // -------------------------

  if (command == "1" ||
      command == "on" ||
      command == "bulb on" ||
      command == "bulbon") {

    digitalWrite(RELAY_PIN, RELAY_ON);

    Serial.println(">>> BULB ON");
  }

  // -------------------------
  // BULB OFF
  // -------------------------

  else if (command == "0" ||
           command == "off" ||
           command == "bulb off" ||
           command == "bulb of" ||
           command == "bulboff" ||
           command == "of") {

    digitalWrite(RELAY_PIN, RELAY_OFF);

    Serial.println(">>> BULB OFF");
  }

  // -------------------------
  // UNKNOWN
  // -------------------------

  else {

    Serial.print("Unknown command: ");
    Serial.println(command);
  }
}

// =================================================
// SETUP
// =================================================

void setup() {

  Serial.begin(115200);

  delay(1000);

  Serial.println();
  Serial.println("================================");
  Serial.println("ESP32 BULB CONTROL");
  Serial.println("================================");

  // Relay setup
  pinMode(RELAY_PIN, OUTPUT);

  // Start with bulb OFF
  digitalWrite(RELAY_PIN, RELAY_OFF);

  // WiFi
  connectWiFi();

  // Subscribe to feed
  mqtt.subscribe(&bulbControl);

  // MQTT
  connectMQTT();

  Serial.println("System ready!");
}

// =================================================
// LOOP
// =================================================

void loop() {

  // Reconnect WiFi if necessary
  if (WiFi.status() != WL_CONNECTED) {
    connectWiFi();
  }

  // Reconnect MQTT if necessary
  if (!mqtt.connected()) {
    connectMQTT();
  }

  // Keep MQTT connection alive
  mqtt.processPackets(1000);

  // Check for new feed value
  Adafruit_MQTT_Subscribe *subscription;

  while ((subscription = mqtt.readSubscription(100)) != NULL) {

    if (subscription == &bulbControl) {

      String command = String((char *)bulbControl.lastread);

      processBulbCommand(command);
    }
  }
}

Key sections, in my own words:

  • Wi-Fi + Adafruit IO connection — connectWiFi() joins the protosem network the same way as Task 1, then the Adafruit_MQTT_Client object is configured with my Adafruit IO username and key so connectMQTT() can authenticate to io.adafruit.com on port 1883.
  • Subscribing to the feed — bulbControl is an Adafruit_MQTT_Subscribe pointed at sachinn__s/feeds/bulb-control, and mqtt.subscribe(&bulbControl) in setup() tells the broker to forward me every new value published to that feed.
  • processBulbCommand() — the dashboard toggle can send a few different strings depending on how it's configured, so I trim and lowercase whatever comes in and match it against several ON variants (1, on, bulb on, bulbon) and OFF variants (0, off, bulb off, bulboff) before driving RELAY_PIN HIGH or LOW.
  • Reconnect logic — every pass through loop() checks WiFi.status() and mqtt.connected() and reconnects either one if it dropped, before calling mqtt.processPackets(1000) and reading the subscription queue — this is what keeps the relay in sync even after a brief Wi-Fi hiccup.

07Configuration

  1. Create a free Adafruit IO account and note the username (sachinn__s)
  2. Create a feed named bulb-control under Feeds → New Feed
  3. Create a new dashboard, name it Bulb Control, and add a Toggle block linked to the bulb-control feed
  4. Open View AIO Key, copy the username and key into the sketch's AIO_USERNAME / AIO_KEY fields, and keep the key out of the public repo

09Challenges & Fixes

  • MQTT authentication kept failing — the Serial Monitor printed a connect error instead of "Connected to Adafruit IO!", which turned out to be an old AIO key left in the sketch from an earlier test. I regenerated the key from the dashboard's key dialog and swapped it into AIO_KEY, and the connection went through on the first try after that.
  • The topic name had to match exactly — I originally typed the feed name slightly differently in the sketch than the feed I'd actually created on Adafruit IO, so subscribing silently did nothing since the topic didn't exist. Double-checking the feed's key on the Feeds page against AIO_USERNAME "/feeds/bulb-control" in the code fixed it.
  • The toggle block didn't send the value I expected — depending on how I set up the Toggle block, Adafruit IO sometimes published ON/OFF text instead of 1/0. Rather than fight the dashboard's default labels, I made processBulbCommand() accept several equivalent strings (on, bulb on, bulbon, and so on), so the relay responds correctly no matter which format the block sends.

10Reflection

The biggest difference from Task 1's local web server is that I no longer need to know the ESP32's IP address at all. In Task 1, the browser had to reach the ESP32 directly, so both devices had to share a network and I had to re-read the IP every time it changed. Here, the ESP32 only ever makes an outbound connection to Adafruit IO, and the dashboard talks to Adafruit IO too — the broker in the middle means I can flip the bulb from my phone on mobile data, nowhere near the protosem Wi-Fi, and it still works.

Publish/subscribe also changed how I think about the connection between "client" and "server." Neither side is really either one — the dashboard publishes to a feed, the ESP32 subscribes to that same feed, and Adafruit IO just routes the message between whoever's interested. That decoupling is what let me swap the relay/bulb hardware in without touching anything about how the dashboard is built.
